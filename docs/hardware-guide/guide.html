Créer ses propres quincailleries

OpenCutList {{VERSION}} · Outil Smart Join (connecteurs, ferrures, charnières) · Descripteur JSON, géométrie paramétrique et fichiers SKP · macOS et Windows · mis à jour le {{DATE}}

1. Principe

Une quincaillerie de la bibliothèque d'OpenCutList, c'est un fichier JSON (le descripteur) : identité, type, nom, fournisseur, options par défaut de l'outil, et la liste des composants à poser.

Chaque composant a deux parties possibles :

  • hardware : l'objet lui-même (tourillon, charnière, embase…), qui apparaît dans la fiche de débit ;
  • machining : l'usinage creusé dans le panneau (perçage, mortaise, cuvette…).

Une partie se décrit de deux façons :

  • par des primitives, directement dans le JSON : perçages et mortaises pour l'usinage, cylindres et oblongs pour la quincaillerie. OpenCutList génère la géométrie à la pose et l'adapte à l'épaisseur réelle des panneaux. Aucun SKP à dessiner : tourillons, Dominos, vis et Cabineo livrés sont faits ainsi ;
  • par un fichier SKP, pour une forme qu'on ne sait pas décrire en primitives (le corps d'une charnière, un Clamex).

L'outil Smart Join lit le descripteur et pose les composants sur chaque joint, répartis selon les options (décalages, espacement). Il mesure les panneaux là où il pose : le descripteur peut s'en servir dans des variables (profondeur de perçage selon l'épaisseur…) et refuser une position par des asserts (panneau trop mince…).

Chaque type de quincaillerie pose ses composants dans des emplacements (slots) : a pour la première pièce, b pour la pièce en vis-à-vis.

2. Où placer les fichiers

La bibliothèque personnelle (Ma Bibliothèque dans l'outil) est un dossier du compte utilisateur :

macOS

~/Library/Application Support/OpenCutList/library/

Le dossier Library est masqué. Dans le Finder : menu Aller › Aller au dossier… (⇧⌘G), colle le chemin ci-dessus, Entrée.

Windows

%APPDATA%\OpenCutList\library\
= C:\Users\<utilisateur>\AppData\Roaming\
  OpenCutList\library\

Le dossier AppData est masqué. Touche Windows + R, tape %APPDATA%\OpenCutList\library, Entrée.

S'il n'existe pas encore, crée-le à la main (OpenCutList le crée aussi au premier enregistrement dans la bibliothèque).

Un dossier racine par type, et un dossier components qui contient les SKP en reproduisant la même arborescence, avec un sous-dossier au nom du fichier JSON (sans l'extension). Les exemples de ce guide écrivent les chemins avec / ; sous Windows, l'explorateur les affiche avec \.

library/
├─ connectors/                          ← descripteurs de type "connector"
│  └─ mon-fournisseur/
│     ├─ tourillon-8x30.json            ← tout en primitives : aucun SKP
│     └─ clamex-maison.json             ← hardware en SKP, usinage en primitives
├─ fittings/                            ← type "fitting"
├─ hinges/                              ← type "hinge"
│  └─ hettich/
│     └─ sensys-110.json
└─ components/                          ← les géométries SKP, et elles seules
   ├─ connectors/mon-fournisseur/clamex-maison/
   │  └─ a.skp                          ← hardware du slot a
   └─ hinges/hettich/sensys-110/
      ├─ a.overlay.skp                  ← slot a, variante "overlay"
      ├─ a.overlay.machining.skp
      ├─ …
      ├─ b.skp
      └─ b.machining.skp

Les sous-dossiers (mon-fournisseur, hettich…) sont libres : ils apparaissent tels quels dans la barre de bibliothèque de l'outil, sous Bibliothèques › Ma Bibliothèque. La Bibliothèque OCL (livrée avec l'extension) est en lecture seule : ne la modifie pas, elle est écrasée à chaque mise à jour.

Nom des fichiers SKP

Quand une partie vaut true dans le JSON, OpenCutList cherche le fichier :

components/<dossier du JSON>/<nom du JSON>/<slot>[.<variante>][.machining].skp
DéclarationFichier attendu
slot a, "hardware": truea.skp
slot a, "machining": truea.machining.skp
slot a, variante inset, "machining": truea.inset.machining.skp
slot b, "hardware": trueb.skp
Si tu renommes le JSON, renomme aussi son dossier dans components. Un fichier déclaré mais absent est une erreur : la quincaillerie apparaît en rouge « manquante » dans la barre.

3. Le descripteur JSON

Fichier texte encodé en UTF-8. Exemple minimal, un tourillon Ø8×30 décrit uniquement par des primitives :

{
  "format": "ocl-hardware",
  "version": 1,
  "id": "3f1c7a52-8d0e-4b6a-9f21-5c4e7d2a9b10",
  "type": "connector",
  "name": "Tourillon 8x30",
  "supplier": "Mon fournisseur",
  "url": "https://www.example.com",
  "components": {
    "a": {
      "name": "Tourillon hêtre 8x30", "price": 0.05,
      "hardware":  { "cylinders": [ { "diameter": "8mm", "from": "-15mm", "to": "15mm" } ] },
      "machining": { "drillings": [ { "diameter": "8mm", "depth": "16mm" } ] },
      "attributes": { "symmetrical": true }
    },
    "b": { "machining": { "same_as": "a" } }
  },
  "options": {
    "height": "/2", "start_offset": "37mm", "end_offset": "37mm", "max_spacing": "500mm"
  }
}

Le slot a pose le tourillon entier (un cylindre de −15 à +15 mm, qui traverse le joint) et son perçage de 16 mm dans la pièce A ; le slot b ne pose qu'un perçage, le même que celui de A, creusé dans B. La section 5 montre comment adapter les profondeurs à l'épaisseur des panneaux.

Un composant peut aussi être { "same_as": "a" } (même composant que le slot a), { "mirror_of": "a" } (le même, posé en miroir) ou null (slot vide, p. ex. ferrure posée d'un seul côté). Il faut au moins un slot non vide, et chaque composant doit avoir au moins une partie.

Variantes (charnières)

Pour une charnière, le slot a peut changer selon la pose de la porte, détectée automatiquement : overlay (en applique), half_overlay (jumelée), inset (encastrée).

"a": {
  "attributes": { "role": "hinge", "hinge_max_angle": 110 },
  "variants": {
    "select": { "by": "hinge_kind" },
    "fallback": "overlay",
    "items": {
      "overlay":      { "name": "Sensys 110° en applique", "hardware": true, "machining": true,
                        "attributes": { "hinge_pivot": [ 17, -29 ] } },
      "half_overlay": { "name": "Sensys 110° jumelée",     "hardware": true, "machining": true,
                        "attributes": { "hinge_pivot": [ -4, -26 ] } },
      "inset": null
    }
  }
},
"b": {
  "name": "Embase Sensys", "price": 1.20, "hardware": true,
  "machining": { "drillings": [
    { "x": "-16mm", "y": "37mm", "diameter": "5mm", "depth": "12mm" },
    { "x":  "16mm", "y": "37mm", "diameter": "5mm", "depth": "12mm" }
  ] }
}
  • fallback : variante utilisée quand le cas détecté n'est pas listé ;
  • une variante à null signifie « non supportée » : pas de repli, la charnière n'est pas posée dans ce cas ;
  • les name, description, price, url, mass, z_offset, attributes d'une variante complètent / remplacent ceux du composant.

Attributs lus par l'action Interagir (ouvrir la porte) : role = "hinge", hinge_max_angle (degrés), hinge_pivot = [x, y] en mm dans le repère de la charnière, hinge_pivot_approximate (booléen).

Nom des pièces dans la fiche de débit

La pièce posée prend le name du composant, remplacé par celui de la variante s'il existe ; une variante sans name ajoute son libellé entre parenthèses. L'usinage ajoute « (Usinage) ». Un composant sans name prend le nom de la quincaillerie, suivi du slot pour b : « Tourillon 8x30 (b, Usinage) ». Le nom est réappliqué à chaque pose : un renommage dans le JSON se propage au modèle.

4. Géométrie paramétrique

Les primitives sont décrites dans le repère de pose du composant (section 6) : la face de la pièce est à z = 0, la matière vers −Z. Les longueurs sont des textes avec unité ou des nombres en millimètres ; x et y valent 0 par défaut. Toute longueur peut être une expression de mesures et de variables (section 5).

PrimitivePartieClésForme
drillingsmachiningx, y, diameter, depthperçage qui part de la face et s'enfonce de depth ; "through" = débouchant
mortisesmachiningx, y, length, width, depthmortaise à bouts ronds : length le long de X (bouts compris), width le long de Y
cylindershardwarex, y, diameter, from, tocylindre le long de Z, de from à to ; il peut traverser le plan du joint
oblongshardwarex, y, length, width, from, totenon à bouts ronds (le pendant d'une mortaise), le long de Z
"hardware":  { "oblongs":  [ { "length": "19mm", "width": "5mm",
                                "from": "-15mm", "to": "15mm" } ] },
"machining": { "mortises": [ { "length": "19mm", "width": "5mm", "depth": "15mm" } ] }

Un débouchant ("through") suit l'épaisseur réelle mesurée à chaque pose : une définition est générée par épaisseur. Le nombre de segments des cercles est fixé par OpenCutList selon le diamètre.

Perçage le long de Y

Un perçage ou une mortaise peut suivre Y avec "axis": "y" ("z" par défaut). Il part alors de la face vers laquelle pointe +Y, à la distance @height de l'ancre, et s'enfonce vers −Y. On le place par x et z (z négatif, dans la pièce) ; sa depth est une longueur, jamais "through". C'est le trou d'accès d'un Clamex, percé dans la face voisine du joint :

"machining": { "drillings": [
  { "axis": "y", "z": "-7.5mm", "diameter": "6mm", "depth": "@height" }
] }

La largeur d'une mortaise le long de Y se mesure alors le long de Z ; "length_axis": "z" met au contraire sa longueur le long de Z (le logement de collerette d'un Cabineo). Les primitives hardware restent le long de Z.

Têtes : fraisure et lamage

Un perçage ou un cylindre peut s'évaser à un bout, en un seul solide :

  • "countersink": { "diameter": "8.5mm", "angle": 90 } : un cône (fraisure, tête fraisée) ; angle vaut 90° par défaut ;
  • "counterbore": { "diameter": "10mm", "depth": "4mm" } : un palier (lamage, tête cylindrique).

Le bout se choisit par "face": "contact" | "opposite" dans la tête d'un perçage (opposite exige "depth": "through") et par "end": "from" | "to", obligatoire, dans celle d'un cylindre.

5. Mesures, variables et asserts

À chaque position, l'outil mesure les pièces. Une longueur peut s'en servir : "@thickness - 2mm", "@thickness / 2". Les littéraux portent une unité (mm, cm, m, ", ', yd), un nombre nu est un facteur, et on n'additionne que des longueurs entre elles.

MesureCe que c'est
@thicknessépaisseur de la pièce derrière la face, vers −Z (l'étendue de toute la pièce)
@thickness_min, @thickness_maxdistance de la face opposée juste derrière les primitives du slot, la plus proche et la plus lointaine ; elles diffèrent quand les faces ne sont pas parallèles. "through" = @thickness_max
@heightdistance de l'ancre à la face de la pièce vers +Y : la face d'où part un perçage le long de Y. Pour un connecteur, c'est la hauteur de pose
@thickness_a, @height_b…la mesure de la pièce du slot a ou b : la même expression se lit depuis l'un ou l'autre slot

Fonctions (arguments séparés par ;) : min(…; …), max(…; …) ; floor(x; v1; v2; …) prend la plus grande valeur proposée qui ne dépasse pas x, ceil(x; v1; v2; …) la plus petite qui n'est pas en dessous : les crans d'une machine, p. ex. floor(@thickness_a - 5mm; 12mm; 15mm; 20mm; 25mm; 28mm) pour la Domino DF 500. Sans valeur qui convienne, l'expression échoue et la position est refusée.

variables (à la racine) nomme des expressions calculées dans l'ordre : chacune peut utiliser les mesures et les variables au-dessus d'elle. asserts liste des comparaisons (<=, >=, <, >, =) : là où l'une échoue, l'outil écarte la position, la marque d'une croix rouge et affiche la comparaison non respectée.

Exemple (le Dowel 8x40 livré) : un tourillon de 40 mm entre deux panneaux, jamais percé à moins de 5 mm de la face opposée. Entre un panneau à plat et un panneau sur chant, il s'enfonce plus dans le chant ; deux panneaux à plat n'offrent pas la place et sont refusés.

"variables": {
  "depth_a": "min(@thickness_a - 5mm; max(20mm; 40mm - (@thickness_b - 5mm)))",
  "depth_b": "40mm - @depth_a"
},
"asserts": [ "@depth_a <= @thickness_a - 5mm", "@depth_b <= @thickness_b - 5mm" ],
"components": {
  "a": {
    "hardware":  { "cylinders": [ { "diameter": "8mm", "from": "-@depth_a", "to": "@depth_b" } ] },
    "machining": { "drillings": [ { "diameter": "8mm", "depth": "@depth_a + 1mm" } ] },
    "attributes": { "symmetrical": true }
  },
  "b": { "machining": { "drillings": [ { "diameter": "8mm", "depth": "@depth_b + 1mm" } ] } }
}
Slots a / b (connecteurs). Les géométries du slot a sont toujours posées sur la pièce A de l'outil (celle dont on sélectionne l'arête, qui touche B par la face voisine), celles du slot b sur la pièce B. Un descripteur a donc un sens : quand ses asserts refusent la position, c'est la jonction qu'il faut prendre depuis l'autre pièce.

Exemple (la Screw 4x50 livrée) : vis qui se visse dans A à travers B, tête fraisée sur la face opposée de B, refusée si cette face n'est pas parallèle ou si la vis mord moins de 15 mm dans A :

"variables": { "embed": "50mm - @thickness_max_b" },
"asserts": [
  "@thickness_max_b - @thickness_min_b <= 0.2mm",
  "@embed >= 15mm",
  "@embed <= @thickness_a - 3mm"
],
"components": {
  "a": {
    "hardware":  { "cylinders": [ { "diameter": "4mm", "from": "-@embed", "to": "@thickness_max_b",
                                    "countersink": { "diameter": "8mm", "end": "to" } } ] },
    "machining": { "drillings": [ { "diameter": "3mm", "depth": "@embed" } ] }
  },
  "b": { "machining": { "drillings": [ { "diameter": "4mm", "depth": "through" } ] } }
}

6. Construire les fichiers SKP

Le repère de pose

C'est le point essentiel, pour les SKP comme pour les primitives : OpenCutList pose chaque composant en faisant coïncider son origine et ses axes avec le repère de pose calculé sur le joint. La géométrie d'un SKP doit donc être dessinée par rapport à l'origine du modèle SketchUp.

TypeOrigineAxes
connectorpoint d'ancrage, sur la face de contact entre les deux piècesX le long de l'arête, +Z sort de la pièce vers l'autre pièce, +Y vers la face de l'arête choisie ; matière en −Z
fittingsur la ligne du joint (l'arête commune)X le long du joint, +Z = normale de la face (sortante), la face s'étend en ±Y ; matière en −Z
hingesur la ligne d'articulation, face arrière de la porte (a) / face intérieure du côté (b)X le long de l'articulation, +Z sort de la face (vers le caisson pour a) ; matière en −Z
Le plus sûr : partir d'un SKP livré. Copie un fichier de la Bibliothèque OCL de même type (p. ex. components/hinges/blum/clip-top/ ou components/connectors/lamello/clamex/), ouvre-le, remplace la géométrie en gardant la même position par rapport à l'origine, puis enregistre-le sous le nouveau nom. La Bibliothèque OCL est dans le dossier de l'extension :
macOS : ~/Library/Application Support/SketchUp 20xx/SketchUp/Plugins/ladb_opencutlist/library/
Windows : %APPDATA%\SketchUp\SketchUp 20xx\SketchUp\Plugins\ladb_opencutlist\library\

Étapes dans SketchUp

  1. Nouveau modèle vide, en millimètres.
  2. Modélise la pièce directement autour de l'origine selon le repère ci-dessus (pas de groupe englobant nécessaire : le contenu du fichier devient le composant).
  3. Hardware : l'objet visible, avec ses matières si tu veux. Usinage : de préférence un volume fermé (solide) représentant la matière enlevée, placé côté −Z. Un usinage simple (perçages, mortaises) est plus robuste en primitives qu'en SKP ; on peut mélanger, p. ex. un hardware en SKP et son usinage en primitives.
  4. Tout sur la balise Untagged (Layer0) : les balises des pièces sont gérées par les options de l'outil.
  5. Pas besoin d'attributs OpenCutList dans le SKP : tout vient du JSON (name, price, attributes…), qui l'emporte toujours.
  6. Purge le modèle (Fenêtre › Infos sur le modèle › Statistiques › Purger), puis Fichier › Enregistrer sous, avec le nom conventionnel, dans le bon dossier components/…. Pour un partage avec d'anciennes versions, choisis le format le plus ancien disponible (SketchUp 2017 minimum).
Une géométrie déjà présente dans le modèle est réutilisée : un SKP modifié n'apparaît pas tant que l'ancienne définition y reste. Pour tester une modification, supprime les poses puis purge le modèle, ou travaille dans un nouveau modèle. Relance l'outil après avoir modifié les fichiers.

7. Vérifier et dépanner

  1. Dans SketchUp, lance Smart Join, choisis l'action du bon type (connecteurs / ferrures / charnières).
  2. Dans la barre de bibliothèque : Bibliothèques › Ma Bibliothèque, puis ton sous-dossier ; clique la quincaillerie pour la choisir.
  3. Pose-la sur un joint de test et vérifie l'orientation (hardware dans le joint, usinage dans la matière). Essaie aussi des épaisseurs et des positions (à plat, sur chant) qui doivent être refusées.
SymptômeCause probable
La quincaillerie n'apparaît pasJSON mal formé (virgule en trop, guillemets), format absent, fichier dans le mauvais dossier racine pour son type
Elle apparaît en rouge « manquante »descripteur invalide (id manquant, slot inconnu, composant sans partie, clé de primitive inconnue, variable @… inconnue…) ou SKP introuvable : vérifier noms et dossier components/…/<nom du JSON>/

Pièce posée à l'envers / décaléegéométrie mal placée par rapport à l'origine ou aux axes du repère de pose

Charnière absente sur une porte encastréevariante inset à null, ou absente sans fallback

Pour valider la syntaxe d'un JSON, ouvre-le dans un éditeur qui signale les erreurs (VS Code, sur macOS comme sur Windows), ou colle-le dans un validateur JSON en ligne.
