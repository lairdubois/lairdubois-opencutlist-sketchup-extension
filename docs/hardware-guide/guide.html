Créer ses propres quincailleries

OpenCutList {{VERSION}} · Outil Assembler (connecteurs, raccords, charnières) · Éditeur, descripteur JSON, géométrie paramétrique, héritage, articles et fichiers SKP · macOS et Windows · mis à jour le {{DATE}}

1. Principe

Une quincaillerie de la bibliothèque d'OpenCutList, c'est un fichier JSON (le descripteur) : identité, type, nom, fournisseur, options par défaut de l'outil, et la liste des composants à poser.

Chaque composant a deux parties possibles :

  • hardware : l'objet lui-même (tourillon, charnière, embase…), qui apparaît dans la fiche de débit ;
  • machining : l'usinage creusé dans le panneau (perçage, mortaise, cuvette…).

Une partie se décrit de deux façons :

  • par des primitives, directement dans le JSON : perçages, mortaises et poches pour l'usinage, cylindres, oblongs et prismes pour la quincaillerie. OpenCutList génère la géométrie à la pose et l'adapte à l'épaisseur réelle des panneaux. Aucun SKP à dessiner : tourillons, Dominos, vis et Cabineo livrés sont faits ainsi ;
  • par un fichier SKP, pour une forme qu'on ne sait pas décrire en primitives (le corps d'une charnière, un Clamex).

L'outil Assembler lit le descripteur et pose les composants sur chaque joint, répartis selon les options (décalages, espacement). Il mesure les panneaux là où il pose : le descripteur peut s'en servir dans des variables (profondeur de perçage selon l'épaisseur…) et refuser une position par des asserts (panneau trop mince…).

Chaque type de quincaillerie pose ses composants dans des emplacements (slots) : a pour la première pièce, b pour la pièce en vis-à-vis.

Trois mécanismes évitent de tout réécrire : les réglages (une variable que l'éditeur propose de modifier, section 6), l'héritage (une quincaillerie qui n'écrit que ce qui change par rapport à une autre, section 7) et les articles (une quincaillerie faite de plusieurs pièces, dont des connecteurs de la bibliothèque, section 8).

Le plus simple est de passer par l'éditeur de quincailleries (section 2) : il écrit le JSON et les SKP à ta place, et montre la quincaillerie posée sur un banc d'essai. Le reste du guide décrit le JSON qu'il produit, pour qui veut l'écrire ou le comprendre.

2. L'éditeur de quincailleries

Dans l'outil Assembler, choisis l'action du bon type (Ajouter des connecteurs, des raccords ou des charnières). La barre de bibliothèque ouvre l'éditeur de deux façons :

  • + dans un dossier de Ma Bibliothèque : une quincaillerie neuve, pré-remplie avec le type et les options de l'action ;
  • le bouton Modifier cette quincaillerie sur la quincaillerie choisie. Une quincaillerie de la Bibliothèque OCL s'ouvre en lecture seule.

À gauche, le banc d'essai pose la quincaillerie sur deux panneaux fictifs (épaisseurs et assemblage réglables : en L, en T, chant contre chant, face contre face ; en applique, jumelée ou encastrée pour une charnière). Sous le banc, les Calculs donnent chaque variable et chaque condition : une seule fausse et l'assemblage est refusé. À droite, trois onglets :

OngletContenu
Réglagesle nom, les réglages publiés (section 6) et les options de l'outil
Piècespar slot, et par variante pour une charnière, deux listes sans menu de type : la pièce, une liste d'articles (section 8), et l'usinage, un SKP suivi de ses primitives. Une liste vide n'est pas posée ; tant qu'elle est vide, la case Même que la reprend de l'autre slot. Pour un SKP : choisir un fichier, le transformer (rotations, miroir, centrage), ou le Créer / Modifier dans SketchUp
JSONle descripteur entier ; chaque modification recalcule le banc et affiche les erreurs

Créer / Modifier dans SketchUp pose un banc temporaire à côté de ton modèle et ouvre la pièce en édition, ses axes étant le repère de pose (section 9). Une petite palette Terminer / Annuler remplace l'éditeur ; à la fin, le banc quitte le modèle et la pièce est enregistrée à la validation.

3. Où placer les fichiers

La bibliothèque personnelle (Ma Bibliothèque dans l'outil) est un dossier du compte utilisateur :

macOS

~/Library/Application Support/OpenCutList/library/

Le dossier Library est masqué. Dans le Finder : menu Aller › Aller au dossier… (⇧⌘G), colle le chemin ci-dessus, Entrée.

Windows

%APPDATA%\OpenCutList\library\
= C:\Users\<utilisateur>\AppData\Roaming\
  OpenCutList\library\

Le dossier AppData est masqué. Touche Windows + R, tape %APPDATA%\OpenCutList\library, Entrée.

S'il n'existe pas encore, crée-le à la main (OpenCutList le crée aussi au premier enregistrement dans la bibliothèque).

Un dossier racine par type, et un dossier components qui contient les SKP en reproduisant la même arborescence, avec un sous-dossier au nom du fichier JSON (sans l'extension). Les exemples de ce guide écrivent les chemins avec / ; sous Windows, l'explorateur les affiche avec \.

library/
├─ connectors/                          ← descripteurs de type "connector"
│  └─ mon-fournisseur/
│     ├─ tourillon-8x30.json            ← tout en primitives : aucun SKP
│     └─ clamex-maison.json             ← hardware en SKP, usinage en primitives
├─ fittings/                            ← type "fitting"
│  └─ equerre-40x40.json                ← articles : un SKP et des vis
├─ hinges/                              ← type "hinge"
│  └─ hettich/
│     └─ sensys-110.json
└─ components/                          ← les géométries SKP, et elles seules
   ├─ connectors/mon-fournisseur/clamex-maison/
   │  └─ a.skp                          ← hardware du slot a
   ├─ fittings/equerre-40x40/
   │  └─ a.body.skp                     ← article "body" du slot a
   └─ hinges/hettich/sensys-110/
      ├─ a.overlay.skp                  ← slot a, variante "overlay"
      ├─ a.overlay.machining.skp
      ├─ …
      ├─ b.skp
      └─ b.machining.skp

Les sous-dossiers (mon-fournisseur, hettich…) sont libres : ils apparaissent tels quels dans la barre de bibliothèque de l'outil Assembler, sous Bibliothèques › Ma Bibliothèque. La Bibliothèque OCL (livrée avec l'extension) est en lecture seule : ne la modifie pas, elle est écrasée à chaque mise à jour.

Nom des fichiers SKP

Quand une partie vaut true dans le JSON, OpenCutList cherche le fichier :

components/<dossier du JSON>/<nom du JSON>/<slot>[.<variante>][.machining].skp

Un article "skp": true (section 8) a le sien, nommé par sa clé : <slot>[.<variante>].<clé>.skp.

DéclarationFichier attendu
slot a, "hardware": truea.skp
slot a, "machining": truea.machining.skp
slot a, variante inset, "machining": truea.inset.machining.skp
slot b, "hardware": trueb.skp
slot a, article body, "skp": truea.body.skp

Ce dossier est géré par OpenCutList : à chaque validation dans l'éditeur, les fichiers qui suivent ces noms et qu'aucune partie ni aucun article ne déclare plus sont supprimés, puis le dossier s'il est vide. Les autres fichiers sont laissés. Renommer la quincaillerie, ou la clé d'un article, renomme son dossier ou son fichier.

Hors de l'éditeur, si tu renommes le JSON, renomme aussi son dossier dans components. Un fichier déclaré mais absent est une erreur : la quincaillerie apparaît en rouge « manquante » dans la barre.

4. Le descripteur JSON

Fichier texte encodé en UTF-8. Exemple minimal, un tourillon Ø8×30 décrit uniquement par des primitives :

{
  "format": "ocl-hardware",
  "version": 1,
  "id": "3f1c7a52-8d0e-4b6a-9f21-5c4e7d2a9b10",
  "type": "connector",
  "name": "Tourillon 8x30",
  "supplier": "Mon fournisseur",
  "url": "https://www.example.com",
  "components": {
    "a": {
      "name": "Tourillon hêtre 8x30", "price": 0.05,
      "hardware":  { "cylinders": [ { "diameter": "8mm", "from": "-15mm", "to": "15mm" } ] },
      "machining": { "drillings": [ { "diameter": "8mm", "depth": "16mm" } ] },
      "attributes": { "symmetrical": true }
    },
    "b": { "machining": { "same_as": "a" } }
  },
  "options": {
    "height": "/2", "start_offset": "37mm", "end_offset": "37mm", "max_spacing": "500mm"
  }
}

Le slot a pose le tourillon entier (un cylindre de −15 à +15 mm, qui traverse le joint) et son perçage de 16 mm dans la pièce A ; le slot b ne pose qu'un perçage, le même que celui de A, creusé dans B. La section 6 montre comment adapter les profondeurs à l'épaisseur des panneaux.

Un composant peut aussi être { "same_as": "a" } (même composant que le slot a), { "mirror_of": "a" } (le même, posé en miroir) ou null (slot vide, p. ex. ferrure posée d'un seul côté). Il faut au moins un slot non vide, et chaque composant doit avoir au moins une partie. Une partie en primitives peut être vide, {} : rien n'est posé, mais l'éditeur la garde, prête à recevoir ses primitives.

Variantes (charnières)

Pour une charnière, le slot a peut changer selon la pose de la porte, détectée automatiquement : overlay (en applique), half_overlay (jumelée), inset (encastrée).

"a": {
  "attributes": { "role": "hinge", "hinge_max_angle": 110 },
  "variants": {
    "select": { "by": "hinge_kind" },
    "fallback": "overlay",
    "items": {
      "overlay":      { "name": "Sensys 110° en applique", "hardware": true, "machining": true,
                        "attributes": { "hinge_pivot": [ "17mm", "-29mm" ] } },
      "half_overlay": { "name": "Sensys 110° jumelée",     "hardware": true, "machining": true,
                        "attributes": { "hinge_pivot": [ "-4mm", "-26mm" ] } },
      "inset": null
    }
  }
},
"b": {
  "name": "Embase Sensys", "price": 1.20, "hardware": true,
  "machining": { "drillings": [
    { "x": "-16mm", "y": "37mm", "diameter": "5mm", "depth": "12mm" },
    { "x":  "16mm", "y": "37mm", "diameter": "5mm", "depth": "12mm" }
  ] }
}
  • fallback : variante utilisée quand le cas détecté n'est pas listé ;
  • une variante à null signifie « non supportée » : pas de repli, la charnière n'est pas posée dans ce cas ;
  • les name, description, price, url, mass, attributes d'une variante complètent / remplacent ceux du composant.

Attributs lus par l'action Interagir (ouvrir la porte) : role = "hinge", hinge_max_angle (degrés), hinge_pivot = [y, z], deux longueurs dans le repère de pose (Y vers le chant de rotation de la porte, Z vers le caisson) ; l'onglet Pièces de l'éditeur les règle sous « Cinématique de la charnière », hinge_pivot_approximate (booléen).

Nom des pièces dans la fiche de débit

La pièce posée prend le name du composant, remplacé par celui de la variante s'il existe ; une variante sans name ajoute son libellé entre parenthèses. L'usinage ajoute « (Usinage) ». Un composant sans name prend le nom de la quincaillerie, suivi du slot pour b : « Tourillon 8x30 (b, Usinage) ». Un article sans name (section 8) prend le nom de son composant suivi de sa clé : « Équerre 40x40 (body) ». Le nom est réappliqué à chaque pose : un renommage dans le JSON se propage au modèle.

5. Géométrie paramétrique

Les primitives sont décrites dans le repère de pose du composant (section 9) : la face de la pièce est à z = 0, la matière vers −Z. Les longueurs sont des textes avec unité ou des nombres en millimètres ; x et y valent 0 par défaut. Toute longueur peut être une expression de mesures et de variables (section 6).

PrimitivePartieClésForme
drillingsmachiningx, y, diameter, depthperçage qui part de la face et s'enfonce de depth ; "through" = débouchant
mortisesmachiningx, y, length, width, depth, length_axismortaise à bouts ronds : length le long de X (bouts compris), width le long de Y ; "length_axis": "y" les inverse ; depth comme un perçage, "through" = traversante
cylindershardwareaxis, x, y, z, diameter, from, tocylindre le long de son axe (Z par défaut), de from à to ; il peut traverser le plan du joint
oblongshardwareaxis, length_axis, x, y, z, length, width, from, totenon à bouts ronds (le pendant d'une mortaise), le long de son axe (Z par défaut)
prismshardwareaxis, from, to, outlinecontour quelconque extrudé le long de son axe, de from à to : platine, équerre, biscuit (voir plus bas)
pocketsmachiningaxis, depth, outlinepoche : un contour creusé dans la pièce sur depth depuis la face, rainure, logement de platine (voir plus bas)
"hardware":  { "oblongs":  [ { "length": "19mm", "width": "5mm",
                                "from": "-15mm", "to": "15mm" } ] },
"machining": { "mortises": [ { "length": "19mm", "width": "5mm", "depth": "15mm" } ] }

Un débouchant ("through") suit l'épaisseur réelle mesurée à chaque pose : une définition est générée par épaisseur. Le nombre de segments des cercles est fixé par OpenCutList selon le diamètre.

Perçage le long de Y

Un perçage, une mortaise ou une poche peut suivre Y avec "axis": "y" ("z" par défaut). Il part alors de la face vers laquelle pointe +Y, à la distance @height de l'ancre, et s'enfonce vers −Y. On le place par x et z (z négatif, dans la pièce) ; sa depth est une longueur, jamais "through". C'est le trou d'accès d'un Clamex, percé dans la face voisine du joint :

"machining": { "drillings": [
  { "axis": "y", "z": "-7.5mm", "diameter": "6mm", "depth": "@height" }
] }

Sur le slot b d'une charnière ou d'une ferrure, le sens est inversé : la pièce part du joint vers +Y, son chant voisin du joint est donc vers −Y. Le perçage part de ce chant, à @height de l'ancre vers −Y (0 en applique, l'épaisseur de la porte en encastrée), et s'enfonce vers +Y ; une fraisure ou un lamage reste sur ce chant. Les vis de la patte fixe d'une charnière plate, dans le chant avant du montant :

"b": { "machining": { "drillings": [
  { "axis": "y", "x": "-14mm", "z": "-10mm", "diameter": "2mm", "depth": "12mm" }
] } }

La largeur d'une mortaise le long de Y se mesure alors le long de Z ; "length_axis": "z" met au contraire sa longueur le long de Z (le logement de collerette d'un Cabineo). Un cylindre, un oblong et un prisme suivent leur propre axis.

Cylindre et oblong couchés

Un cylindre ou un oblong peut se coucher le long de X ou de Y avec "axis": "x" ou "y" ("z" par défaut). from et to se mesurent alors le long de cet axe, et on le place par les deux autres, comme les points d'un prisme : y et z le long de X, x et z le long de Y (0 par défaut). Contrairement à un perçage le long de Y, il ne part d'aucune face : @height n'intervient pas. La longueur d'un oblong suit le premier de ces deux axes (x le long de Z ou de Y, y le long de X) ; "length_axis" la met le long du second. Une vis couchée en travers du joint, 8 mm sous la face :

"hardware": { "cylinders": [
  { "axis": "x", "z": "-8mm", "diameter": "4mm", "from": "-10mm", "to": "10mm" }
] }

Prismes : platines, équerres et poches

Un prisme est un contour fermé extrudé le long de son axis : "z" par défaut, "x" ou "y". Ses points se donnent par les deux autres axes : x et y le long de Z, y et z le long de X, x et z le long de Y (0 par défaut). r arrondit le coin d'un point, du rayon donné. Le sens de parcours est libre, mais le contour ne doit pas se croiser, et chaque arrondi doit tenir sur ses deux côtés. Il n'a pas de x ni de y propres : le contour le place. Une équerre de 30 × 30 mm, épaisse de 2 mm et large de 40 mm, son pli arrondi à l'intérieur :

"hardware": { "prisms": [ { "axis": "x", "from": "-20mm", "to": "20mm", "outline": [
  { "y": 0, "z": 0 }, { "y": "30mm", "z": 0 }, { "y": "30mm", "z": "2mm" },
  { "y": "2mm", "z": "2mm", "r": "1mm" }, { "y": "2mm", "z": "30mm" }, { "y": 0, "z": "30mm" }
] } ] }

Comme toute quincaillerie générée, un prisme est centré en Z à la pose : la même pièce décalée par les mesures reste une seule définition.

En usinage, une poche (pockets) est un contour creusé dans la pièce : ce qu'un perçage ou une mortaise ne sait pas former, une rainure, un logement de platine. Elle fonctionne comme eux : elle part de la face et s'enfonce de depth ("through" = débouchante), ou part du chant avec "axis": "y". Son contour se donne comme celui d'un prisme : x et y, ou x et z le long de Y. Elle est posée telle quelle, sans recentrage. Une poche de 40 × 20 mm, ses coins arrondis, profonde de la moitié du panneau :

"machining": { "pockets": [ { "depth": "@thickness / 2", "outline": [
  { "x": "-20mm", "y": "-10mm", "r": "3mm" }, { "x": "20mm", "y": "-10mm", "r": "3mm" },
  { "x": "20mm", "y": "10mm", "r": "3mm" }, { "x": "-20mm", "y": "10mm", "r": "3mm" }
] } ] }

Têtes : fraisure et lamage

Un perçage ou un cylindre peut s'évaser à un bout, en un seul solide :

  • "countersink": { "diameter": "8.5mm", "angle": 90 } : un cône (fraisure, tête fraisée) ; angle vaut 90° par défaut ;
  • "counterbore": { "diameter": "10mm", "depth": "4mm" } : un palier (lamage, tête cylindrique).

Le bout se choisit par "face": "contact" | "opposite" dans la tête d'un perçage (opposite exige "depth": "through") et par "end": "from" | "to", obligatoire, dans celle d'un cylindre.

6. Mesures, variables, réglages et asserts

À chaque position, l'outil mesure les pièces. Une longueur peut s'en servir : "@thickness - 2mm", "@thickness / 2". Les littéraux portent une unité (mm, cm, m, ", ', yd), un nombre nu est un facteur, et on n'additionne que des longueurs entre elles.

MesureCe que c'est
@thicknessépaisseur de la pièce derrière la face, vers −Z (l'étendue de toute la pièce)
@thickness_min, @thickness_maxdistance de la face opposée juste derrière les primitives du slot, la plus proche et la plus lointaine ; elles diffèrent quand les faces ne sont pas parallèles. "through" = @thickness_max
@heightdistance de l'ancre à la face de la pièce vers +Y (vers −Y sur le slot b d'une charnière ou d'une ferrure) : la face d'où part un perçage le long de Y. Pour un connecteur, c'est la hauteur de pose
@height_min, @height_maxle long de la même ligne, la première sortie de la pièce (= @height) et la dernière : @height_max franchit les vides traversés (une rainure au bord de l'ancre) jusqu'au chant de la pièce sur cette ligne. P. ex. "at": [ { "y": "@height_max" } ] pose une pièce au chant, rainure ou pas
@thickness_a, @height_b…la mesure de la pièce du slot a ou b : la même expression se lit depuis l'un ou l'autre slot

Fonctions (arguments séparés par ;) : min(…; …), max(…; …) ; floor(x; v1; v2; …) prend la plus grande valeur proposée qui ne dépasse pas x, ceil(x; v1; v2; …) la plus petite qui n'est pas en dessous : les crans d'une machine, p. ex. floor(@thickness_a - 5mm; 12mm; 15mm; 20mm; 25mm; 28mm) pour la Domino DF 500. Sans valeur qui convienne, l'expression échoue et la position est refusée.

variables (à la racine) nomme des expressions : chacune peut utiliser les mesures et les autres variables, où qu'elles soient écrites ; elles sont calculées dans l'ordre de leurs dépendances (une boucle est une erreur). asserts liste des comparaisons (<=, >=, <, >, =) : là où l'une échoue, l'outil écarte la position, la marque d'une croix rouge et affiche la comparaison non respectée.

Exemple (une version simplifiée du tourillon livré) : un tourillon de 40 mm entre deux panneaux, jamais percé à moins de 5 mm de la face opposée. Entre un panneau à plat et un panneau sur chant, il s'enfonce plus dans le chant ; deux panneaux à plat n'offrent pas la place et sont refusés.

"variables": {
  "depth_a": "min(@thickness_a - 5mm; max(20mm; 40mm - (@thickness_b - 5mm)))",
  "depth_b": "40mm - @depth_a"
},
"asserts": [ "@depth_a <= @thickness_a - 5mm", "@depth_b <= @thickness_b - 5mm" ],
"components": {
  "a": {
    "hardware":  { "cylinders": [ { "diameter": "8mm", "from": "-@depth_a", "to": "@depth_b" } ] },
    "machining": { "drillings": [ { "diameter": "8mm", "depth": "@depth_a + 1mm" } ] },
    "attributes": { "symmetrical": true }
  },
  "b": { "machining": { "drillings": [ { "diameter": "8mm", "depth": "@depth_b + 1mm" } ] } }
}
Slots a / b (connecteurs). Les géométries du slot a sont toujours posées sur la pièce A de l'outil (celle dont on sélectionne l'arête, qui touche B par la face voisine), celles du slot b sur la pièce B. Un descripteur a donc un sens : quand ses asserts refusent la position, c'est la jonction qu'il faut prendre depuis l'autre pièce.

Exemple (une vis 4×50, version simplifiée des vis livrées) : vis qui se visse dans A à travers B, tête fraisée sur la face opposée de B, refusée si cette face n'est pas parallèle ou si la vis mord moins de 15 mm dans A :

"variables": { "embed": "50mm - @thickness_max_b" },
"asserts": [
  "@thickness_max_b - @thickness_min_b <= 0.2mm",
  "@embed >= 15mm",
  "@embed <= @thickness_a - 3mm"
],
"components": {
  "a": {
    "hardware":  { "cylinders": [ { "diameter": "4mm", "from": "-@embed", "to": "@thickness_max_b",
                                    "countersink": { "diameter": "8mm", "end": "to" } } ] },
    "machining": { "drillings": [ { "diameter": "3mm", "depth": "@embed" } ] }
  },
  "b": { "machining": { "drillings": [ { "diameter": "4mm", "depth": "through" } ] } }
}

Réglages

Une variable écrite en objet est un réglage : l'éditeur la montre dans l'onglet Réglages pour qu'on l'ajuste sans toucher aux expressions. Partout ailleurs, elle se lit comme sa valeur : @diameter vaut 8 mm.

CléRôle
valueobligatoire : une longueur simple, sans @ ni fonction
labelle libellé affiché
stepsles valeurs permises, choisies par boutons ; value doit en faire partie
min, maxbornent une saisie libre (pas avec steps)
"variables": {
  "diameter": { "value": "8mm", "label": "Diamètre", "steps": [ "6mm", "8mm", "10mm" ] },
  "length": { "value": "40mm", "label": "Longueur", "min": "20mm", "max": "60mm" },
  "depth_a": "@length / 2"
}

7. Héritage

Une quincaillerie peut en étendre une autre par "extends" et ne déclarer que ce qui change : tourillons 8×40 et 10×40, ou ta version d'une quincaillerie OCL, partagent une même logique. Dans l'éditeur, le bouton Dériver crée une telle quincaillerie, et les valeurs héritées y apparaissent grisées : modifier un réglage ou une option le surcharge.

{
  "format": "ocl-hardware",
  "version": 1,
  "id": "6c0d2e8a-41f7-4b39-9a85-2f7e1c3b5d64",
  "extends": "$OCL/connectors/generic/dowels/dowel.json",
  "name": "Tourillon 8x40 hêtre",
  "variables": {
    "diameter": { "value": "8mm" },
    "clearance": "2mm"
  }
}
  • Parent. Son chemin part de la racine de la même bibliothèque ("connectors/x.json") ; $OCL/… désigne la Bibliothèque OCL depuis Ma Bibliothèque, jamais l'inverse. Huit niveaux au plus ; un parent introuvable ou une boucle rend la quincaillerie invalide.
  • "abstract": true : le parent n'est ni listé ni posable. Il peut laisser un réglage sans value, que chaque enfant donne (le Dowel et la Screw livrés sont ainsi).
  • Fusion, du parent le plus lointain à l'enfant : les objets fusionnent clé par clé, une liste ou une valeur simple remplace celle du parent, null supprime. Ne sont jamais hérités : format, version, id, name, extends, abstract. type est hérité et ne peut pas changer.
Écrit dans l'enfantEffet
"diameter": { "value": "10mm" }change la valeur du réglage, garde son libellé et ses crans
"clearance": "1mm"fige le réglage : une variable simple, plus proposée dans l'éditeur
"b": { "machining": null }retire l'usinage du slot b
"asserts": [ … ]remplace la liste du parent
"asserts": [ "@super", "@depth_a >= 10mm" ]la liste du parent, puis celle de l'enfant
"depth_a": "@super + 1mm"l'expression du parent, entre parenthèses, plus 1 mm

Une partie true héritée telle quelle se lit dans le dossier de pièces du parent ; redéclarée true dans l'enfant, dans celui de l'enfant. Renommer un parent dans l'éditeur réécrit l'extends de ses enfants ; le supprimer est refusé tant qu'il en a.

8. Composition : les articles

Une quincaillerie peut poser plusieurs pièces par slot, chacune sa propre ligne dans la fiche de débit : une équerre et ses vis donnent « Équerre 40x40 × 1 » et « Screw 4x16 × 4 ». La partie hardware d'un composant devient alors un objet d'articles, chacun sous une clé.

Dans l'onglet Pièces de l'éditeur, la pièce est toujours une liste d'articles. Une pièce simple (true, un chemin, des primitives) y apparaît comme un seul article body, et le JSON garde cette forme courte tant que l'article n'a ni position, ni nom propre, ni second article : la pièce est alors posée seule, sans groupe. Cet article n'a pas de champ Nom, il porte celui du composant, et ses prix et masse sont ceux du composant. Dès qu'il faut la forme longue, l'éditeur déplace la description, le prix, l'url et la masse du composant dans body (le groupe des articles n'en porte aucun), et les y remet au retour à la forme courte.

{
  "format": "ocl-hardware",
  "version": 1,
  "id": "9b4e1f30-7a2c-4d8e-b6f5-0c3a9e2d7f18",
  "type": "fitting",
  "name": "Équerre 40x40",
  "variables": {
    "bracket_thickness": { "value": "2mm", "label": "Épaisseur de l'équerre" },
    "hole_distance": { "value": "25mm", "label": "Entraxe des trous" }
  },
  "components": {
    "a": {
      "hardware": {
        "body": { "name": "Équerre 40x40", "price": 0.30, "skp": true },
        "screws": {
          "use": "$OCL/connectors/generic/screws/screw-4x16.json", "host": "a",
          "measures": { "thickness_b": "@bracket_thickness" },
          "variables": { "embed_min": { "value": "10mm" } },
          "at": [ { "x": "-8mm", "y": "-@hole_distance" }, { "x": "8mm", "y": "-@hole_distance" } ]
        }
      }
    },
    "b": {
      "hardware": {
        "screws": {
          "use": "$OCL/connectors/generic/screws/screw-4x16.json", "host": "a",
          "measures": { "thickness_b": "@bracket_thickness" },
          "variables": { "embed_min": { "value": "10mm" } },
          "at": [ { "x": "-8mm", "y": "@hole_distance" }, { "x": "8mm", "y": "@hole_distance" } ]
        }
      }
    }
  }
}
  • Clé : lettres minuscules, chiffres, - et _, en commençant par une lettre, unique dans le slot ; pas le nom d'un champ d'article (name, skp, use, at…). Elle nomme le fichier d'un article "skp": true : a.body.skp.
  • Article propre : ses champs de fiche de débit (name, description, price, url, mass ; sans name, celui du composant suivi de la clé) et sa géométrie, un SKP ("skp" : true ou un chemin partagé) ou des primitives (cylinders, oblongs, prisms).
  • Article de bibliothèque : use désigne un connector concret, par son chemin comme pour extends. Son nom, son prix et ses asserts sont ceux du connecteur, évalués à chaque position : un seul en échec refuse la position. host (a ou b) dit quel côté du connecteur est notre panneau ; l'autre côté est virtuel, measures donne son épaisseur (thickness_b ici : l'épaisseur de l'équerre). variables ne change que les valeurs de ses réglages. Son usinage côté host s'ajoute à celui du slot.
  • Positions : at liste des { x, y, z } dans le repère du slot (longueurs ou expressions, 0 par défaut) ; absent, une position à l'origine. La géométrie d'un article est dessinée autour de sa propre origine. z décale l'article hors de la face : négatif, il s'enfonce (dans une poche) ; positif, il se surélève (sur une cale). C'est ainsi qu'on décale une quincaillerie : un article unique avec son at. Pour un article de bibliothèque, l'épaisseur côté host perd ce qu'il s'enfonce.
  • Seuls les types autres que connector peuvent utiliser un connecteur. Un connecteur utilisé ne peut pas être supprimé ; le renommer dans l'éditeur réécrit les use qui le désignent.

9. Construire les fichiers SKP

Le repère de pose

C'est le point essentiel, pour les SKP comme pour les primitives : OpenCutList pose chaque composant en faisant coïncider son origine et ses axes avec le repère de pose calculé sur le joint. La géométrie d'un SKP doit donc être dessinée par rapport à l'origine du modèle SketchUp.

TypeOrigineAxes
connectorpoint d'ancrage, sur la face de contact entre les deux piècesX le long de l'arête, +Z sort de la pièce vers l'autre pièce, +Y vers la face de l'arête choisie ; matière en −Z
fittingsur la ligne du joint (l'arête commune)X le long du joint, +Z = normale de la face (sortante), la face s'étend en ±Y ; matière en −Z
hingesur la ligne d'articulation, face arrière de la porte (a) / face intérieure du côté (b)X le long de l'articulation, +Z sort de la face (vers le caisson pour a) ; matière en −Z
Le plus sûr : partir d'un SKP livré. Copie un fichier de la Bibliothèque OCL de même type (p. ex. components/hinges/blum/clip-top/ ou components/connectors/lamello/clamex/), ouvre-le, remplace la géométrie en gardant la même position par rapport à l'origine, puis enregistre-le sous le nouveau nom. La Bibliothèque OCL est dans le dossier de l'extension :
macOS : ~/Library/Application Support/SketchUp 20xx/SketchUp/Plugins/ladb_opencutlist/library/
Windows : %APPDATA%\SketchUp\SketchUp 20xx\SketchUp\Plugins\ladb_opencutlist\library\

Étapes dans SketchUp

Le plus simple : dans l'éditeur, onglet Pièces, Créer (ou Modifier) ouvre la pièce dans SketchUp directement dans le bon repère, à côté du banc d'essai, et l'enregistre au bon nom à la validation. À la main :

  1. Nouveau modèle vide, en millimètres.
  2. Modélise la pièce directement autour de l'origine selon le repère ci-dessus (pas de groupe englobant nécessaire : le contenu du fichier devient le composant).
  3. Hardware : l'objet visible, avec ses matières si tu veux. Usinage : de préférence un volume fermé (solide) représentant la matière enlevée, placé côté −Z. Un usinage simple (perçages, mortaises) est plus robuste en primitives qu'en SKP ; on peut mélanger, p. ex. un hardware en SKP et son usinage en primitives.
  4. Tout sur la balise Untagged (Layer0) : les balises des pièces sont gérées par les options de l'outil.
  5. Pas besoin d'attributs OpenCutList dans le SKP : tout vient du JSON (name, price, attributes…), qui l'emporte toujours.
  6. Purge le modèle (Fenêtre › Infos sur le modèle › Statistiques › Purger), puis Fichier › Enregistrer sous, avec le nom conventionnel, dans le bon dossier components/…. Pour un partage avec d'anciennes versions, choisis le format le plus ancien disponible (SketchUp 2017 minimum).
Une géométrie déjà présente dans le modèle est réutilisée : un SKP modifié n'apparaît pas tant que l'ancienne définition y reste. Pour tester une modification, supprime les poses puis purge le modèle, ou travaille dans un nouveau modèle. Relance l'outil après avoir modifié les fichiers.

10. Vérifier et dépanner

Le banc d'essai de l'éditeur montre déjà la pose, les calculs et les conditions. Pour vérifier dans un vrai modèle :

  1. Dans SketchUp, lance Assembler, choisis l'action du bon type (connecteurs / raccords / charnières).
  2. Dans la barre de bibliothèque : Bibliothèques › Ma Bibliothèque, puis ton sous-dossier ; clique la quincaillerie pour la choisir.
  3. Pose-la sur un joint de test et vérifie l'orientation (hardware dans le joint, usinage dans la matière). Essaie aussi des épaisseurs et des positions (à plat, sur chant) qui doivent être refusées.
SymptômeCause probable

L'onglet JSON de l'éditeur signale les erreurs de syntaxe et de validation. Hors de l'éditeur, ouvre le fichier dans un éditeur de texte qui signale les erreurs (VS Code, sur macOS comme sur Windows), ou colle-le dans un validateur JSON en ligne.
